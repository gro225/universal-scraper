# Universal Harvester — руководство

Инструмент собирает по заданной теме разнородный контент (текст + изображения) со всего
интернета и складывает в единое хранилище. Вы описываете задачу в YAML — система сама
находит источники, обходит их, извлекает данные и индексирует.

Архитектура целиком — [ARCHITECTURE.md](ARCHITECTURE.md). Обзор проекта — [README.md](README.md).

---

## 1. Что умеет и чего пока нет

**Умеет (Фаза 0, проверено на живом прогоне):**

- точечный захват: одна страница, список страниц или сайт вглубь — без YAML;
- поиск источников по теме через self-hosted SearXNG, без API-ключей и внешних расходов;
- обход найденных сайтов вглубь с соблюдением `robots.txt` и задержек по доменам;
- извлечение текста, заголовков, авторов, дат — через JSON-LD/OpenGraph и trafilatura;
- рендер SPA-страниц настоящим браузером (тир T1, см. §2) — по умолчанию выключен;
- определение типа документа: `article`, `product`, `profile`, `media_page`, `page`;
- скачивание изображений с дедупликацией по контенту, EXIF и webp-превью;
- три уровня дедупа: URL, точный контент, near-duplicate (simhash считается и пишется);
- оценка релевантности и поиск по смыслу (раздел 6);
- разбор корпуса на подтемы (раздел 7) и извлечение сущностей (раздел 8);
- жёсткие бюджеты прогона: страницы, байты, время;
- полнотекстовый поиск, REST API, SSE-прогресс.

**Пока нет** (это следующие фазы, не пробелы):

| Чего нет | Фаза |
|---|---|
| Обход антибот-защиты (Cloudflare и подобные) — нужен stealth-фетчер | 1 |
| OCR, подписи к картинкам, pHash (поиск по изображению) | 1 |
| Коннекторы к Reddit / Telegram / YouTube / RSS | 2 |
| LLM-извлечение по своей схеме (заготовка есть: `extractors/minify.py`) | 2 |
| Автоматическая дизамбигуация темы — пока только ручные подсказки | 2 |
| Экспорт в Parquet, дашборды, граф сущностей | 3 |

## 2. Установка и запуск

Нужен Docker (Docker Desktop на macOS должен быть **запущен**) и Python 3.12.

```bash
cd universal-scraper
make up            # postgres, redis, minio, meilisearch, searxng, api
```

Поднимутся:

| Сервис | Адрес | Доступ |
|---|---|---|
| API + Swagger | http://localhost:8080/docs | без пароля |
| MinIO (сырьё и картинки) | http://localhost:9001 | `minioadmin` / `minioadmin` |
| Meilisearch | http://localhost:7700 | ключ `harvester-dev-key` |
| SearXNG | http://localhost:8888 | без пароля |
| PostgreSQL | `localhost:5432`, база `harvester` | `harvester` / `harvester` |

Это дефолты для локальной разработки. Перед выносом на сервер их обязательно менять:
порты проброшены на все интерфейсы.

**Локально без контейнера** (инфраструктура всё равно из compose):

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
cp .env.example .env
.venv/bin/harvester migrate
```

### Рендер SPA-страниц — тир T1

Обычный HTTP (тир T0) возвращает то, что прислал сервер. Половина современных сайтов
присылает пустой каркас и рисует содержимое скриптом — такая страница осядет документом
из меню и подвала. Тир T1 догружает её настоящим браузером.

```bash
.venv/bin/pip install -e ".[render]"
.venv/bin/crawl4ai-setup        # один раз: ставит браузеры Playwright, ~600 МБ
```

Затем в `.env`:

```
RENDER_ENABLED=true
```

Как это работает: после каждого ответа T0 считается объём **видимого** текста (без
скриптов, меню и подвала). Если его меньше `RENDER_MIN_TEXT_CHARS` и страница похожа
на каркас SPA — тот же URL берётся браузером, и дальше его разбирает тот же trafilatura.
Замена происходит, только если браузер реально добавил текста; если нет — остаётся
захват T0. Любой сбой T1 (браузер не поднялся, таймаут) тоже откатывается на T0,
прогон из-за этого не падает.

Управление из задачи, в обход эвристики:

```yaml
crawl:
  render: always     # auto (по умолчанию) | always | never
```

`always` — для сайта, про который заранее известно, что без скриптов он пустой:
экономит по одному лишнему запросу T0 на страницу. `never` — когда рендер включён
глобально, но конкретную задачу гнать через браузер не хочется. Режим наследуется
ссылками вглубь, так что задавать его достаточно один раз.

Что почём (замерено локально, без сетевых задержек): старт браузера ~2,5 с один раз
на прогон, дальше ~0,7–1 с на страницу. `RENDER_CONCURRENCY` (по умолчанию 3) держит
число вкладок — оно намеренно меньше `CRAWL_WORKERS`, потому что вкладка стоит сотни
мегабайт, а T1 нужен меньшинству страниц. Сколько страниц ушло в браузер, видно в
счётчике `rendered` в статистике прогона, а тир каждой загрузки пишется в `fetch_log`.

Чего T1 **не** делает — не обходит антибот-защиту. Против Cloudflare нужен stealth-фетчер,
и `RENDER_ON_BLOCK` (пробовать браузер на 403/429) по умолчанию выключен не случайно.

## 3. Первый запуск

Два разных сценария. Начните с первого — он проще.

### А. Конкретные страницы или сайты — без YAML

Когда вы уже знаете адрес:

```bash
harvester grab https://example.com/article        # одна страница
harvester grab example.com --depth 2              # сайт вглубь на 2 уровня
harvester grab a.ru b.ru c.ru --depth 1           # несколько сайтов сразу
harvester grab example.com --depth 3 --no-media --max-pages 200
```

| Флаг | Что делает |
|---|---|
| `--depth N` | `0` (по умолчанию) — только названные страницы; больше — идти по ссылкам |
| `--everywhere` | не ограничиваться доменами исходных адресов |
| `--no-media` | не скачивать изображения |
| `--max-pages N` | предел страниц |
| `--name` | своё имя задачи (иначе генерится, вида `grab-example-com-0807-1745-bc3fa1`) |

Схему можно не писать вовсе: поисковик не задействуется, задача собирается на лету.
Если адрес назвали вы — страница сохранится, даже когда текста на ней мало
(порог `min_text_chars` в этом режиме снят).

Те же три способа помимо CLI:

- **на странице** http://localhost:8080/ui — кнопка «Собрать страницы», вставить адреса
  в поле, выбрать глубину, нажать «Запустить»;
- **из трея** — «Собрать ссылку из буфера»: скопировали ссылку, ткнули пункт меню;
- **по API** — `POST /grab` с `{"urls": [...], "depth": 0}`.

### Б. Поиск по теме

Когда адресов нет, а есть тема — нужен YAML (раздел 4):

```bash
make run TASK=tasks/sol-lemon.yaml
.venv/bin/harvester run tasks/sol-lemon.yaml -v
```

В конце печатается таблица метрик: `seeds`, `fetched`, `documents`, `duplicates`,
`domains`, `media`, `media_skipped`, `errors`, `skipped_robots`, `stop_reason`.

Порядок величин на эталонной задаче: **477 документов, 727 изображений, 112 доменов
за 715 фетчей**, темп ~80 фетчей/мин.

## 4. Task DSL — полный справочник

Нужно указать **либо** `query.subject` (искать по теме), **либо** `discovery.seeds`
(обойти конкретные адреса). Всё остальное имеет разумные дефолты:

```yaml
task: my-topic          # уникальное имя = ключ задачи (можно писать и `name:`)
version: 1

query:
  subject: "Что ищем"                   # или оставить пустым, если заданы seeds
  intent: null                          # зачем ищем — идёт в расширение запроса
  languages: [ru, en]
  include_hints: []                     # сужают выдачу, главное лекарство от шума
  exclude_hints: []

discovery:
  connectors: [searxng]                 # searxng | generic_web
  seeds: []                             # явные точки входа, идут первыми
  extra_queries: []                     # свои запросы к поисковику
  max_seeds: 200
  pages_per_query: 2                    # страниц выдачи на запрос

crawl:
  scope:
    follow: seed_domain                 # none | seed_domain | seed_domain_plus_outlinks
    max_depth: 2
    allow: ["*"]
    deny: ["*/login*", "*/cart*", "*/signup*", "*.exe", "*.zip"]
  politeness:
    respect_robots: true
    delay_per_domain_ms: 1500
    max_concurrency_per_domain: 2
  budget:
    max_pages: 2000
    max_wall_clock_s: 3600
    max_bytes: 5368709120               # 5 ГБ

extract:
  want: [article_text, images, structured_ld, links]
  min_text_chars: 250                   # короче — документ не создаётся
  media:
    download: true
    types: [image]
    min_width: 200
    min_height: 200
    max_per_document: 20
```

### Четыре ручки, которые реально меняют результат

**`include_hints` / `exclude_hints`** — главное. Запрос `"Sol Lemon"` без подсказок притащил
чистящее средство Pine-Sol Lemon Fresh, браслеты из яшмы и рецепт рамена вперемешку
с настоящими находками. Подсказки сужают выдачу до одной интерпретации.

**`crawl.scope.follow`**:
- `none` — только seed'ы. Быстро и чисто, годится для разведки;
- `seed_domain` — вглубь найденных сайтов, но не наружу;
- `seed_domain_plus_outlinks` — плюс соседние домены на один шаг.

**`budget`** — жёсткие. Превышение останавливает прогон и пишет `stop_reason`
(`max_pages` / `max_bytes` / `max_wall_clock`), а не жжёт ресурсы молча.

**`politeness.delay_per_domain_ms`** — узкое место темпа. 1500 мс по умолчанию.
Снижать только там, где вы вправе это делать.

## 5. Интерфейс

Два экрана, оба необязательные — всё то же есть в CLI и API.

### Иконка в строке меню

```bash
pip install -e ".[tray]"     # ставит pystray
harvester-tray
```

Иконка показывает состояние цветом: серое кольцо — простой, зелёное с точкой — идёт обход,
красное — API недоступен. В меню:

| Пункт | Что делает |
|---|---|
| строка сверху | живые счётчики: «Идёт «sol-lemon» · 128 док · 340 изобр» |
| **Собрать ссылку из буфера** | скопировали адрес — забрали страницу, один клик |
| **Запустить задачу** | задачи из БД + YAML-файлы из `tasks/`, которых там ещё нет |
| **Остановить прогон** | виден только во время обхода; собранное сохраняется |
| **Открыть результаты** | страница просмотра (ниже) |
| **Ещё** | Swagger, MinIO, Meilisearch, SearXNG |

По завершении прогона приходит системный баннер с итогом.

Трей ходит **только по HTTP**, в БД и Redis не лезет. Поэтому работает и с удалённым
сервером:

```bash
HARVESTER_API=http://<server-lan-ip>:8080 harvester-tray
```

Переменные: `HARVESTER_API` (адрес API), `HARVESTER_TASKS` (папка с YAML, по умолчанию
`tasks`), `HARVESTER_TRAY_POLL` (период опроса в секундах, по умолчанию 4).

### Страница результатов

**http://localhost:8080/ui** — открывается из трея или напрямую.

- кнопка **«Собрать страницы»** — форма: вставить адреса, выбрать глубину, запустить;
- живой статус прогона в шапке;
- поиск по всему собранному;
- фильтр по задаче;
- вкладка «Документы» — карточки с типом, доменом, датой и числом картинок;
- вкладка «Галерея» — превью всех изображений, клик открывает оригинал.

Страница одна, без сборки, отдаётся самим FastAPI. Тему берёт из системной
(светлая/тёмная).

## 6. Релевантность и поиск по смыслу

Прогон по теме неизбежно тащит омонимы: на `Sol Lemon` половина выдачи оказалась
чистящим средством Pine-Sol. Оценка релевантности отделяет находки от мусора.

### Как считается

```
relevance = cos(документ, что ищем) − cos(документ, что НЕ ищем)
```

**Второе слагаемое решает всё.** Проверено на 477 документах реального прогона:

| Чем оценивали | Что оказалось наверху |
|---|---|
| косинус к теме по заголовку | Pine-Sol и браслеты — бесполезно |
| косинус к теме по полному тексту | Pine-Sol всё ещё третий — бесполезно |
| **с вычитанием антипримера** | только readdork.com, издание про нужную группу |

Антипример берётся из `query.exclude_hints`. Пишите туда не синонимы темы, а **то, чем
омоним притворяется**:

```yaml
query:
  subject: "Sol Lemon"
  include_hints: ["music", "artist", "band"]
  exclude_hints:
    - "чистящее средство, бытовая химия, уборка дома"
    - "товар в интернет-магазине, цена, купить, доставка"
    - "украшения, браслеты, камни"
```

На этих подсказках «Pine-Sol Lady» уехал с 7-го места на 57-е из 487, а при пороге 0.40
остались только 8 документов нужного издания.

Без `exclude_hints` оценка всё равно считается, но на омонимах работает слабо — CLI
предупреждает об этом в начале прогона.

### Оценка ничего не удаляет

Она пишется в `documents.relevance`, а порог применяется **при чтении**. Поэтому порог
можно менять задним числом, ничего не перекрауливая, а подсказки — переигрывать мгновенно:
векторы документов от них не зависят, пересчитываются только якоря.

```bash
harvester embed                  # досчитать оценки для уже собранного
harvester relevance sol-lemon    # гистограмма: какой порог что отсечёт
# поправили exclude_hints в YAML:
harvester rescore sol-lemon      # переоценка одним UPDATE, без модели
```

### Поиск по смыслу

```bash
harvester search "выход нового альбома" --semantic
```

Находит по смыслу, а не по словам: на этот запрос верхние результаты — анонсы альбомов,
хотя дословного совпадения в текстах нет.

На странице `/ui` — выпадающий список «качество» (порог) и галочка «по смыслу».
В карточке документа оценка показана рядом с типом.

### Модель

`paraphrase-multilingual-MiniLM-L12-v2` через **fastembed** (ONNX), 384 измерения, 0.22 ГБ.
Не sentence-transformers: torch на 8 ГБ памяти не ставится. Скорость — ~13 документов/с
на M1, 565 документов посчитались за 42 секунды.

Ставится как extra: `pip install -e '.[embed]'`. В образе уже включён, модель кэшируется
в томе `models` и переживает пересборку.

## 7. Разобраться в теме: подтемы

Релевантность отвечает «насколько документ по теме». Она не отвечает на первый
вопрос человека после прогона — **«что тут вообще есть»**. На него отвечают подтемы.

```bash
harvester topics sol-lemon
```

Корпус из 1187 документов разложился на 60 групп. Верх списка:

| Док. | Релев. | Подтема | Представитель |
|---|---|---|---|
| 31 | +0.30 | youtube, embedded, upload | Lemon Sol — Polymorph (Music Video) |
| 36 | +0.26 | announced, album, released, single, debut | Lemon Sol \| Artist profile |
| 36 | +0.23 | blues, jersey, society, north, music | Tickets \| North Jersey Blues Society |
| 130 | +0.21 | dork, collection, album | Chappell Roan: the Dork collection |
| 117 | −0.11 | cleaner, pine, surface, scent | Pine-Sol Multi-Surface Cleaner |
| 40 | −0.03 | amazon, card, circle, target | Welcome to Amazon Customer Service |

Главное наблюдение: **средняя релевантность по группе делит корпус надёжнее порога
по отдельным документам**. Целую группу видно одним взглядом — «вот эти 117 документов
про бытовую химию» — и её можно отбросить целиком, не перебирая по одному.

Поэтому сортировка по умолчанию — по релевантности, а не по размеру: крупнейшие группы
как раз обычно мусорные. `--by size` переключает.

```bash
harvester topics sol-lemon --by size --min-size 5 --show 20
harvester topics sol-lemon --threshold 0.6     # мельче дробление
```

Порог `--threshold` — косинусное расстояние, при котором документы ещё считаются одной
подтемой. 0.75 подобрано на этом корпусе: ниже дробится на почти-дубли, выше музыка
слипается с бытовой химией.

На странице `/ui` — кнопка «Подтемы»: карточки групп и список сущностей под ними.
Клик по группе фильтрует и документы, и сущности.

### Как это устроено

Агломеративная кластеризация со средней связью по косинусу, поверх тех же векторов,
что считает фильтр релевантности. Число групп заранее неизвестно — его и хотим узнать,
поэтому порог по расстоянию, а не k-means с заданным k.

Алгоритм свой, на numpy (`analysis.py`, 60 строк): sklearn тянет за собой scipy, вместе
145 МБ в образ ради одного метода. 1149 документов разбираются за 3.3 секунды.
Потолок — 5000 документов: матрица расстояний квадратична по памяти.

Названия групп — простая TF-IDF: слова, частые внутри группы и редкие в остальном
корпусе. Интерфейсный мусор («cookie», «subscribe») отфильтрован списком стоп-слов.

## 8. Кто и что упоминается: сущности

Подтемы отвечают «из чего состоит корпус», сущности — **«кто здесь действует»**.

```bash
harvester topics sol-lemon      # сначала подтемы — сущности ищутся внутри них
harvester entities sol-lemon
harvester entities sol-lemon --graph
```

| Док. | Дом. | Тип | Кто или что |
|---|---|---|---|
| 15 | 1 | PER | Lemon Sol |
| 12 | 1 | ORG | North Jersey Blues Society |
| 8 | 1 | ORG | NJBS |
| 6 | 1 | MISC | Omni 'Verse |
| 2 | 2 | MISC | Manteca |

`--graph` показывает, кто с кем упоминается рядом: «Music Video — Lemon Sol» ×8,
«Fontaines D.C. — The North» ×6.

### Два вывода, определившие устройство

**Извлекать надо внутри подтем, а не по всему корпусу.** По всему корпусу верх списка
занимают WestJet, Lotto Max и Donald Trump — сущности тонут в мусоре, которого
в корпусе большинство. Поэтому команда берёт только подтемы не ниже `--min-relevance`
(0.15) и не мельче `--min-size` (5 документов). Снизьте пороги, если корпус чище.

**Без модели не обойтись.** Извлечение заглавных словосочетаний той же TF-IDF, что
работает для названий подтем, даёт «All», «Now», «The», «Every» — артикли и начала
предложений. spaCy отличает имя от определителя.

### Отсев интерфейсного шума

NER исправно находит «Log In», «Buy Tickets», «Конфиденциальность» и «Google LLC» —
это навигация и подвал, а не действующие лица. Их снимают:

- словарь `UI_WORDS` в `entities.py` — пополняйте под свои источники;
- требование встретиться минимум в двух документах подтемы;
- отсев склеек вроде «playingLemon Sol» — следа потерянного пробела в разметке.

Шум всё равно просачивается: «Music Video» и «London» формально сущности, но действующими
лицами их назвать трудно. Смотрите на колонку «дом.»: сущность с нескольких доменов
надёжнее той, что живёт на одном.

### Установка

```bash
pip install -e '.[entities]'
python -m spacy download xx_ent_wiki_sm      # 39 МБ
```

В Docker-образ spaCy **не входит**: извлечение сущностей — это ручной шаг после прогона,
а не часть обхода, в отличие от эмбеддингов. Команда работает локально.

Сущности глобальны (уникальны по имени и типу): один и тот же человек в разных задачах —
одна запись. Граф совместных упоминаний отдельной таблицы не требует, он выводится
соединением `document_entities` с самой собой.

## 9. CLI

```bash
harvester migrate                     # применить миграции схемы
harvester run <task.yaml> [-v]        # полный прогон задачи по YAML
harvester grab <url...> [--depth N]   # собрать конкретные адреса, без YAML
harvester stats <run_id>              # метрики прогона
harvester embed [--task N]            # досчитать оценки релевантности
harvester rescore <задача>            # переоценить после правки подсказок
harvester relevance <задача>          # гистограмма оценок и выбор порога
harvester topics <задача>             # разложить корпус на подтемы
harvester entities <задача> [--graph] # кто и что упоминается
harvester search "запрос" [--semantic] [--task-id ...] [--limit N]
harvester connectors                  # список зарегистрированных источников
```

Внутри контейнера — через `docker compose exec api harvester ...` или `make shell`.

## 10. HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/healthz` | проверка живости |
| `POST` | `/grab` | собрать конкретные адреса: `{"urls": [...], "depth": 0}` — создаёт задачу и сразу запускает |
| `POST` | `/tasks` | создать задачу; принимает YAML (`Content-Type: text/yaml`) или JSON |
| `GET` | `/tasks` | список задач с числом документов |
| `GET` | `/tasks/{task_id}` | прочитать задачу |
| `POST` | `/tasks/{task_id}/runs` | запустить прогон, возвращает `run_id` |
| `GET` | `/runs?active=true` | текущие прогоны; попутно чистит записи без пульса |
| `POST` | `/runs/{run_id}/stop` | остановить прогон (работает и для запущенных из CLI) |
| `GET` | `/runs/{run_id}` | состояние и метрики прогона |
| `GET` | `/runs/{run_id}/events` | SSE-поток прогресса |
| `GET` | `/items` | список документов; фильтры `task_id`, `domain`, `min_relevance`, `topic_id`, `limit`, `offset` |
| `POST` | `/search` | поиск: `{"q": "...", "semantic": true, "min_relevance": 0.2}` |
| `GET` | `/tasks/{id}/topics` | подтемы задачи |
| `GET` | `/tasks/{id}/entities` | действующие лица; `topic_id` сужает до подтемы |
| `GET` | `/tasks/{id}/entity-graph` | кто с кем упоминается рядом |
| `GET` | `/tasks/{id}/relevance` | гистограмма оценок задачи |
| `GET` | `/media` | список изображений для галереи |
| `GET` | `/media/{media_id}?thumb=true` | редирект на подписанную ссылку к файлу |
| `GET` | `/ui` | страница просмотра результатов |

```bash
curl -X POST localhost:8080/tasks -H 'Content-Type: text/yaml' --data-binary @tasks/my.yaml
curl -X POST localhost:8080/tasks/$TASK_ID/runs
curl -N localhost:8080/runs/$RUN_ID/events
curl "localhost:8080/items?task_id=$TASK_ID&limit=20"
```

Интерактивно — Swagger на http://localhost:8080/docs.

Весь цикл через API проверен end-to-end: `POST /tasks` (201) → `POST /runs` (202) →
SSE отдаёт `planned` и `completed` → `GET /runs` показывает `state: completed` с метриками →
`GET /items` возвращает собранные документы.

## 11. Где смотреть результаты

**Поиск:**

```bash
harvester search "запрос"
curl -X POST localhost:8080/search -H 'Content-Type: application/json' -d '{"q":"запрос"}'
```

**Картинки:** `http://localhost:8080/media/<id>?thumb=true`

**Сырьё глазами:** консоль MinIO на :9001, бакет `harvester`:
- `raw/{task_id}/{run_id}/{sha[:2]}/{sha}` — исходный HTML как пришёл;
- `media/{sha[:2]}/{sha}` и `.thumb.webp` — файлы, дедуплицированные по контенту.

**SQL:** `docker compose exec postgres psql -U harvester -d harvester`

```sql
-- по доменам, с числом картинок
select d.domain, count(*) docs, count(dm.media_id) media
  from documents d left join document_media dm on dm.document_id = d.id
 group by 1 order by 2 desc limit 20;

-- перепечатки: один контент — много источников
select title, array_length(source_urls, 1) sources
  from documents where array_length(source_urls, 1) > 1 order by 2 desc;

-- что не получилось достать
select error, count(*) from fetch_log where error is not null group by 1 order by 2 desc;
```

## 12. Модель данных

| Таблица | Что хранит |
|---|---|
| `tasks`, `runs` | задачи и прогоны со снапшотом DSL (воспроизводимость) |
| `documents` | нормализованные документы: текст, метаданные, `payload jsonb`, `source_urls[]` |
| `media_assets` | файлы, дедуплицированные глобально по `sha256` |
| `document_media` | связь M:N с ролью (`hero` / `inline` / ...) |
| `entities`, `document_entities` | действующие лица и их связь с документами |
| `topics` | подтемы корпуса |
| `links` | граф гиперссылок между документами |
| `fetch_log` | провенанс: каждый запрос, статус, время, ссылка на сырьё |

Ключевое: `documents` и `media_assets` — граждане одного класса. Картинка не приложение
к тексту, а самостоятельная запись со своими метаданными.

## 13. Свой источник

Реализовать четыре метода и зарегистрировать — ядро о конкретных сайтах не знает:

```python
# harvester/connectors/my_source.py
from .base import register

class MyConnector:
    name = "reddit"
    def matches(self, ref): ...          # берусь ли за этот URL
    async def discover(self, task): ...  # тема -> seed-ссылки
    async def fetch(self, ref): ...      # достать сырьё, ничего не парсить
    def extract(self, raw, task): ...    # -> Document + MediaRef + links

register(MyConnector())
```

Дальше: импорт в `connectors/__init__.py`, имя в `discovery.connectors` задачи.
Образцы — `searxng.py` (только discovery) и `generic_web.py` (полный цикл).

### Типовые проблемы

| Симптом | Причина и что делать |
|---|---|
| `Cannot connect to the Docker daemon` | не запущен Docker Desktop |
| `plan: 0 seed'ов` | SearXNG отдаёт не JSON. В `deploy/searxng/settings.yml` в `formats` должен быть `json` |
| Много `403` в `fetch_log` | норма: ~14% фетчей упираются в антибот-защиту. Это граница HTTP-тира, снимется Playwright'ом в Фазе 1 |
| Ссылка на картинку не открывается | `S3_PUBLIC_ENDPOINT` должен указывать на адрес MinIO, видимый браузеру (хост входит в подпись) |
| Обход идёт медленно | упирается в `delay_per_domain_ms`, а не в сеть. Ожидаемый темп ~80 фетчей/мин |
| `stop_reason: infrastructure_failure` | 10 подряд сбоев Redis/БД у воркера. Проверьте `make logs` и здоровье контейнеров |

## 15. Правовое

Краулер по умолчанию соблюдает `robots.txt`, держит паузу между запросами к одному домену
и не обходит авторизацию или paywall. Есть защита от обращений во внутреннюю сеть (SSRF).

Краулер честно представляется в заголовке `User-Agent` как `UniversalHarvester`, не маскируясь
под браузер, поэтому правила `robots.txt` для ботов на него действуют. Строку можно поменять
через `USER_AGENT` в `.env`, например добавить контакт для администраторов сайтов.
Ответственность за соответствие ToS конкретных источников и законодательству о персональных
данных лежит на операторе системы.
